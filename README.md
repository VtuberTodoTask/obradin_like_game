# 漁り屋（ASARIYA）— シェルター推理ゲーム 試作版

[docs/ai/DESIGN.md](docs/ai/DESIGN.md) の設計書に基づく HTML プロトタイプ。

## 遊び方

`index.html` をブラウザで開くだけで動く（サーバー不要・外部ライブラリなし）。

- `index.html?seed=123` のようにシードを指定すると、同じシナリオを再現できる。
- 進行状況とメモはブラウザの localStorage に保存される。

## LLM による文章化（OpenAI API）

API キーを設定すると、主観ログの文章を LLM が住人ごとの語り口で書き直す。未設定ならテンプレート文のまま遊べる。

1. `js/config.local.example.js` を `js/config.local.js` にコピーする（作成済みならそのまま）
2. `apiKey` に OpenAI の API キーを書く。必要ならモデル名なども変える
3. `index.html` を開き直す。シナリオを開くと自動で文章化が始まる

`js/config.local.js` は `.gitignore` で git 管理外なので、キーはコミットされない。
キーはブラウザから OpenAI に直接送られるので、このフォルダを公開サーバーに置かないこと。

処理の流れ（設計書 §10。詳しくは [docs/ai/SPEC.md](docs/ai/SPEC.md) §8）：

1. 生成の前に「物語の正本」（いつ・どこで・誰がいて・何が起きたかの場面の時系列と因果）を作ってある（`js/story.js`）。
2. 生成の単位は場面。同じ場面を記録する書き手全員を1回の呼び出しでまとめて書かせる。
   各書き手には、本人が見聞きした出来事だけを渡す。場面カードにない出来事・人物・物は書かせず、足してよいのは感覚・感情・内面だけ。
3. 時系列順の「波」で生成し、合格した文章で具体化された細部（台詞・物の状態など）を正本に書き戻して、後の場面に渡す。
4. 往復検証：別の呼び出しで手がかり事実・本文が主張する出来事・細部を抽出し、書き漏らし・書きすぎ・場面カードにない出来事を検出する。
5. 日ごとの整合性検査：同じ日の複数のログを並べ、矛盾がないかを LLM に判定させる。
6. 不合格のエントリは指摘を添えて再生成（最大3回）。それでも通らなければエラーを表示し、
   「さらに再検証する」か「テンプレート文を使う」かを選ぶ。
7. 1回のリクエストは `timeoutSec`（既定 120 秒）で打ち切って再送する。通信エラーが続いたときも、
   「再試行する」か「テンプレート文で遊ぶ」（後で「LLMで文章化」から再開できる）かを選ぶ。

結果はシードとモデルごとにブラウザに保存されるので、同じシナリオを開き直しても API は呼ばない。
テンプレート文を選んだエントリも記録され、再送はしない（作り直すときは「検証器」の「キャッシュを消して作り直す」）。
1シナリオあたり API 呼び出しはおおよそ 45 回、所要 4 分ほど（gpt-5-mini）。

## 構成

| ファイル | 設計書 | 役割 |
|---|---|---|
| `js/config.js` | §3, §4.2, §14 | 職能コード表・規模・確率などの設定 |
| `js/util.js` | — | シード付き乱数、時刻表記 |
| `js/generator.js` | §6 | 生成パイプライン [1]〜[7], [9]（住人・関係・事件・状態・解錠グラフ・ログ・JSON） |

| `js/narrator.js` | §10 | 文章化 [8] のテンプレート版（LLM の下書きにもなる） |
| `js/llm.js` | §10 | OpenAI API による文章化と往復検証 |
| `js/config.local.js` | — | API キーなどのローカル設定（git 管理外。`config.local.example.js` から作る） |
| `js/solver.js` | §8 | CSP ソルバー、到達可能性・一意性・文章の往復検証 |
| `js/game.js` | §12.1-3 | プレイ用 UI ＋ 検証器パネル |
| `tools/batch-check.js` | §12.3 | Node で多数のシードを生成・検証する |

```
node tools/batch-check.js 1 20        # シード 1〜20 を生成して検証
node tools/batch-check.js --dump 3    # シード 3 のシナリオ JSON を出力
node tools/batch-check.js 1 3 --llm   # LLM で文章化して往復検証まで行う（API を呼ぶ）
```

画面右上の「検証器」からも、検証レポートの表示・一括検証・JSON の入出力ができる。

## 設計書との違い（試作のための割り切り）

- **言語**：Python ではなく JavaScript（ブラウザ単体で動かすため）。
- **ソルバー**：OR-Tools／Z3 の代わりに、AC-3 とバックトラックによる小さな CSP ソルバーを自前で実装。
  ID の3要素（区画・入居順・職能）は互いに制約を持たないので、3つの CSP に分けて解いている。
- **文章化**：論理層の生成時にはテンプレートで文章を作り、LLM はその後で主観ログだけを書き直す。
  相談役と管理AIの会話ログは、管理AIの機械的な口調が合っているのでテンプレートのまま。
- **往復検証の失敗時**：設計書ではシナリオを破棄して [3] からやり直すが、API の費用がかさむため、
  通らなかったエントリだけを、プレイヤーの選択で再検証するかテンプレート文で確定する。
- **資料の追加**：侵入者（トリック4）の所在を一意に決めるため、管理AIが機械的に記録する
  「外部ハッチ開閉記録」を初期資料として加えた。
